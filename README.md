## 1. 项目愿景与边界约束 (Project Scope)
本项目旨在基于受限的 MCU 资源，从零构建一个具备语音交互、物理动作与表情反馈的桌面陪伴机器人。项目核心不仅在于实现功能，更在于践行**工业级嵌入式软件工程规范**。

### 1.1 核心约束条件 (Constraints)
* **算力上限**：STM32F103C8T6 (ARM Cortex-M3, 72MHz)。
* **内存红线**：Flash 64KB / SRAM 20KB。系统极度贫裸，**严禁使用动态内存分配（`malloc`/`free`）**，所有数据交换必须依赖静态内存或环形缓冲区（Ring Buffer）。
* **开发工具链**：彻底摒弃 Keil IDE，全面采用 `CMake` 构建系统 + `ARM-GCC` 交叉编译链，配合 `Git` 进行版本追踪。

## 3. 核心风险评估与对策 (Risk Management)
* **电气风险**：动作执行机构（如舵机）堵转电流巨大，极易拉低 3.3V 逻辑供电导致单片机死机复位。
  * *对策*：严禁电机与单片机共用 3.3V LDO 取电。必须采用双电源或独立 5V 降压方案，且保持共地。
* **内存溢出风险 (Stack Overflow)**：F103 的 20KB SRAM 极易被显存和局部数组耗尽。
  * *对策*：OLED 显存按单色位图计算，限制全局变量使用；严禁在中断函数中声明大型数组。
* **时序阻塞风险**：OLED I2C 刷屏耗时较长，容易错过串口语音数据。
  * *对策*：串口接收必须使用中断 + 环形缓冲区甚至 DMA；业务逻辑层采用状态机。

## 5. 软件工程分层架构 (Software Architecture)
系统代码严格遵循“公私接口分离”与“高内聚低耦合”原则。
* **app/**：核心业务逻辑层 (大脑：只做逻辑决策，如情绪切换)
* **bsp/**：板级支持包 (四肢与五官：只做寄存器与模块底层通信)
* **铁律**：`bsp/` 下绝对不能出现业务状态判断；主循环严禁使用 `delay_ms` 死等。
