### 🕳️ 2. 走的弯路与思维纠偏
1. **备忘录误区（.txt vs .md）**：
   * *原想法*：想用 `.txt` 记事本或者腾讯文档随便记记引脚和说明。
   * *纠偏*：做硬件极其讲究引脚对齐，`.txt` 换台电脑排版就会乱，容易导致引脚接错烧片子。必须用 Markdown (`.md`) 锁死表格格式。且文档必须跟代码放在同一个 Git 仓库里，像“沉金 PCB”一样绑定在一起，绝不能代码和说明书分家。
2. **急于求成误区（还没想好就想写代码）**：
   * *原想法*：觉得功能还没定，现在没法建工程，等功能定好了再写。
   * *纠偏*：正规军的做法是**“留出骨架，按需填空”**。哪怕外设还没买，也要先把工程的文件夹（BSP/APP）建好，把引脚分配表（哪怕是空的）画好。用空表反向约束未来的采购和接线。

```bash

# 6. 把本地文件推送到云端仓库的主分支

② 架构认知：APP 与 BSP 到底是什么？
BSP (板级支持包)：单片机的四肢与五官。只管底层寄存器和引脚。比如只负责“给电机发 PWM 波”，完全不管电机为什么要转。

APP (业务逻辑层)：单片机的大脑。只做战略决策，绝对不碰具体的引脚配置。比如大脑决定“如果听到人说话，就命令电机转头”。

好处：以后如果要换电机型号，只改 BSP 即可，APP 里的核心逻辑一行都不用动。

💡 5. 学长的老派忠告
做电信工程，“慢就是快”。
很多新手拿到板子，一上来就把 FreeRTOS、OLED、电机全塞进一个 main.c 里，一编译 100 多个报错，最后直接放弃。
我们要像搭积木一样，今天只做一件事，做通了就 Git 存盘。永远保证手里的代码是“可编译、不死机”的，这就是做嵌入式最顶级的素养。
