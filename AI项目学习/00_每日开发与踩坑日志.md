### 🕳️ 2. 走的弯路与思维纠偏
1. **备忘录误区（.txt vs .md）**：
   - *原想法*：想用 `.txt` 记事本或者腾讯文档随便记记引脚和说明。
   - *纠偏*：做硬件极其讲究引脚对齐，`.txt` 换台电脑排版就会乱，容易导致接错线烧片子。必须用 Markdown 锁死表格格式，且文档必须跟代码绑定在同一个 Git 仓库里，绝不能代码和说明书分家。
2. **急于求成误区（还没想好就想写代码）**：
   - *原想法*：觉得功能还没定，等定好了再建工程。

3. **工具叠加误区（以为 CMake 可以和 Keil 混用）**：
   - *原想法*：电脑里本来就有 Keil5，以为只要再下载个 CMake 配合着用就行。
   - *纠偏*：Keil5 自带了编译器和构建体系，而 CMake 的使命就是**替代** Keil 的构建体系。两者是互斥的，强行混用会导致系统崩溃。

#### ② 架构认知：APP 与 BSP 到底是什么？

* **BSP (板级支持包)**：单片机的**四肢与五官**。只管底层寄存器和引脚。比如只负责“给电机发 PWM 波”，完全不管电机为什么要转。
* **APP (业务逻辑层)**：单片机的**大脑**。只做战略决策，不碰具体引脚。比如大脑决定“如果听到人说话，就命令电机转头”。
* *好处*：以后换电机型号，只改 BSP，APP 核心逻辑一行不用动。

#### ③ 编译工具链底层逻辑：“全包快餐店” vs “米其林后厨”

* **传统模式 (Keil5 = 快餐店)**：点一下 Build 就出固件，但过程完全黑盒，且被死死绑定在 Windows 系统上，无法做企业级 CI/CD 自动化编译。
* **工业界模式 (现代跨平台工具链 = 米其林后厨)**：
1. **CMake（餐厅经理）**：负责看懂我的 `CMakeLists.txt`，画出详细的工程构建图纸。
2. **Ninja（包工头/执行总监）**：拿着图纸，调度电脑 CPU 多核极速并发干活（编译速度秒杀 Keil）。
3. **arm-none-eabi-gcc（掌勺大厨）**：真正的编译器，负责把 C 语言翻译成 STM32 认识的机器码。



#### ④ Markdown 避坑指南：排版失效的隐形杀手

* **语法铁律**：标题 `#` 或列表项 `-` / `*` 后，**必须紧跟一个英文半角空格**；区块之间必须留**空行**；行首绝对不能有莫名其妙的空格缩进。
* **插入图片**：图片必须随工程走，保存在 `assets/` 文件夹下，使用相对路径：`![说明](assets/图片名.png)`

# 桌面陪伴机 - 每日开发与踩坑实录

## 2026-10-10：功能定稿与硬件扫雷，以物理边界驱动设计

### 🎯 1. 今日进度
- **功能 MVP 封版**：经过多轮算力推演，正式敲定了第一期（V1.0）核心功能组合（参数化表情、番茄钟、温湿度、无源蜂鸣器音效、离线语音+按键兜底）。
- **状态机定型**：明确了系统核心的 4 大工作模式（待机陪伴、专注番茄、休息奖励、免打扰休眠），为后续 FreeRTOS 任务划分打下地基。
- **硬件采购评估**：排查了手头现有的元器件。确认了手头的 DHT11 是带有上拉电阻和电源指示灯的“神仙级”成品模块，避免了裸件飞线的硬件坑。

---

### 🕳️ 2. 走的弯路与思维纠偏
1. **动画显示误区（GIF vs 参数化绘制）**：
   - *原想法*：想直接找网上的 `.gif` 动图放在 0.96 寸 OLED 上播。
   - *纠偏*：F103 的 64KB Flash 根本塞不下几十帧的全尺寸位图，且解压极耗 RAM。正规军做法是**参数化几何绘制**，纯靠数学函数（画圆弧、矩形）组合表情，通过变动宽高参数实现眨眼和情绪，代码仅占几百字节，0 溢出风险。
2. **网络功能盲目堆叠（ESP8266 危机）**：
   - *原想法*：想外挂 Wi-Fi 模块获取天气和时间。
   - *纠偏*：在 FreeRTOS 下，解析天气返回的庞大 JSON 文本会瞬间把剩余的 10KB RAM 干爆（Stack Overflow）。一期工程必须果断做减法，先用 F103 内部的 RTC 做本地时间。
3. **交互过于理想化（全语音控制的隐患）**：
   - *原想法*：全靠离线语音模块控制，够酷炫。
   - *纠偏*：没有实体按键兜底，在图书馆或深夜寝室等静音场景下，设备将直接瘫痪。加上 1 个多功能轻触按键（单击/双击/长按）才是高可靠性的工业设计。

---

### 📦 3. 今日核心收获（详细备忘）

#### ① 硬件元器件选型的“内行门道”
- **蜂鸣器必须买“无源”**：有源蜂鸣器通电只会发出刺耳尖叫；无源蜂鸣器配合单片机定时器输出 PWM，能奏出不同音阶的和弦音（比如 R2-D2 机器人音效），质感直接拉满。注意：必须买带三极管驱动的模块，单片机引脚直接推会烧毁 IO 口。
- **OLED 屏幕认准 I2C (4针)**：只需占用单片机 2 根引脚（SCL、SDA），省下的宝贵 GPIO 可以留给按键和外设。

#### ② 传感器避坑实录：单总线的“悬空死穴” (以 DHT11 为例)
- **底层原理**：DHT11 走单总线（1-Wire）协议，物理层严格要求数据线（DAT）必须外接一个 4.7kΩ~10kΩ 的上拉电阻，否则总线会处于浮空的高阻态，单片机读到的全是死机乱码。
- **实战确幸**：今天确认了我手上的 DHT11 是带 PCB 底板的 3 针模块版。底板上不仅提前焊好了 10kΩ 贴片上拉电阻，还带了一颗电源指示灯，接错线或没供电一眼就能看出来，省去了极大的硬件 Debug 成本。

#### ③ 核心状态机 (FSM) 架构流转
在不动手写代码前，必须把单片机的大脑状态固化：
- **A. 待机态**：OLED 随机眨眼，轮询温湿度，监听串口（语音）与按键。
- **B. 专注态**：切入番茄钟倒计时，屏蔽外界打扰，蜂鸣器静音。
- **C. 奖励态**：番茄钟结束，蜂鸣器奏乐，表情变开心，显示休息倒计时。
- **D. 休眠态**：息屏断电降功耗，仅留板载 PC13 呼吸灯。

### 💡 5. 学长的老派忠告

**“在没算清电气账之前，绝不通电。”**
很多新手以为写代码最难，其实硬件选型和接线才是地基。选错了裸件（比如没上拉电阻的传感器、没驱动电路的蜂鸣器），你在软件层写出花来也读不到数据。买对一个好模块，能帮你省下一星期的 Debug 青春。
