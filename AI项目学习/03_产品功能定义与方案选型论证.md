# 桌面陪伴小助理 - 产品功能定义与方案选型论证 (MVP V1.0)

## 1. 项目定位与物理边界约束 (架构设计的基石)
* **产品定位**：带番茄钟与温湿度显示功能的桌面效率助理，兼具情绪互动陪伴感。
* **软件架构**：基于 FreeRTOS 实时操作系统，采用 CMake + ARM-GCC 交叉编译工具链。
* **物理算力红线（STM32F103C8T6）**：
  * **SRAM 极度贫血 (20KB)**：引入 FreeRTOS 后，内核与任务堆栈起步开销约 10KB，业务层可用 RAM 仅剩约 10KB。
  * **Flash 容量有限 (64KB)**：无法存放全尺寸多帧位图。
  * **算力限制 (72MHz)**：不支持复杂的音频 DSP 软解码、大批量 JSON 文本解析及全局屏幕抗锯齿渲染。
  * **结论**：所有功能设计必须遵循“最小内存开销、外包高算力需求、硬件模块化解耦”的原则。

## 2. 功能池筛选与决策演进记录 (Trade-off 过程)

在首轮讨论中，我们评估了市面上常见的陪伴机功能，并基于上述红线进行了严格的取舍与迭代：

### 2.1 视觉交互：OLED 动态表情显示
* **最初想法**：直接在网上找现成的 `.gif` 动图文件在屏幕上播放。
* **否决理由**：F103 无法进行 GIF 软解码。若将 30 帧动图拆解为 128x64 位图阵列，将直接吃掉约 30KB Flash，导致系统存储空间过载。
* **最终方案**：采用**“参数化几何绘制”**。纯靠数学函数（画圆弧、矩形）组合成眼睛，通过改变高度和宽度参数实现“眨眼”、“弯月牙（开心）”、“变窄（专注）”。代码仅占几百字节，0 显存溢出风险。

### 2.2 声音交互：时钟提醒与系统反馈
* **最初想法**：番茄钟结束时，依靠屏幕闪烁或直接用普通有源蜂鸣器发出“滴滴”声。
* **否决理由**：屏幕闪烁在用户低头看书时极易被忽略；有源蜂鸣器声音刺耳，缺乏机器人的科技陪伴感。
* **最终方案**：采用**无源蜂鸣器模块（带三极管驱动）**。单片机通过定时器输出 PWM 方波，调节频率奏出不同音高的和弦音阶（如星战 R2-D2 机器人的“哔嘟哔嘟”提示音），提升情绪反馈质感。

### 2.3 网络与扩展：Wi-Fi 天气与时间同步
* **最初想法**：外挂 ESP8266 模块，通过 Wi-Fi 获取网络天气和精确时间。
* **否决理由（高危隐患）**：通过 HTTP 获取天气会返回冗长的 JSON 文本。在剩余 RAM 不足 10KB 的环境下，调用 `cJSON` 解析会导致 FreeRTOS 任务栈极大概率溢出（Stack Overflow），系统死机。此外，校园/公司网络的 Portal 认证会令 ESP8266 瘫痪。
* **最终方案**：**一期工程（MVP）果断砍掉 Wi-Fi 功能**。时间基准由 F103 内部自带的 RTC（实时时钟）外设提供（需板载 32.768kHz 晶振支持）。网络模块留作后续二期升级储备。

### 2.4 交互控制：离线语音控制 vs 实体按键
* **最初想法**：利用单片机做语音识别，或通过外接模块实现全语音控制切换表情、打开番茄钟。
* **工程隐患**：单片机无算力进行音频特征提取；同时，全语音控制在图书馆/深夜等静音场景下会彻底失效。
* **最终方案（双重冗余交互）**：
  1. **语音外包**：外挂 SU-03T 离线语音模组，STM32 只负责通过 UART 接收翻译好的极简 Hex 指令。
  2. **物理兜底**：增加 1 个实体轻触按键作为备用交互入口（单击番茄钟启停，双击切屏，长按全局静音）。

### 2.5 传感器：环境温湿度 (DHT11)
* **方案确认**：保留 DHT11 单总线读取。
* **已知风险与应对**：DHT11 时序对微秒级延迟极度敏感。在 FreeRTOS 中，读取温湿度的 5ms 内，必须加入临界区保护（关全局中断），防止被任务调度器打断导致数据校验失败。需注意硬件端加入 10kΩ 上拉电阻。

## 3. 最终敲定的硬件模块清单 (MVP 版本)

基于以上论证，一期工程（V1.0）硬件采购池确立如下：
1. **核心板**：STM32F103C8T6 最小系统板（已有）
2. **显示器**：0.96寸 OLED 屏幕（4 针 I2C 接口）
3. **传感器**：DHT11 温湿度传感器（已有）
4. **音频**：无源蜂鸣器模块（必须带三极管/S8050 驱动电路）
5. **交互 A**：SU-03T 离线语音模组（带底板排针版，走串口通信）
6. **交互 B**：普通两脚轻触按键模块（利用单片机内部弱上拉，软件消抖）

## 4. 系统核心状态机（4 大工作模式流转）

系统架构以 FreeRTOS 任务调度为基础，业务逻辑被抽象为以下 4 种有限状态机（FSM）模式：

* **模式 A【待机巡航态 (Companion)】**：
  * **行为**：OLED 循环播放动态表情（随机眨眼）；后台每隔 2s 轮询 DHT11，温湿度超标时表情切换为“眩晕/冒汗”；随时监听语音串口与按键中断。
* **模式 B【专注番茄态 (Focus)】**：
  * **进入条件**：语音指令“开始学习”或单击按键。
  * **行为**：默认 25 分钟倒计时；屏幕上部显示专注眼神，下部显示进度条；蜂鸣器静音，屏蔽非紧急交互。
* **模式 C【休息奖励态 (Break)】**：
  * **进入条件**：番茄钟倒计时归零。
  * **行为**：蜂鸣器播放欢快提示音；表情切换为欢快月牙眼，屏幕滚动显示当前温湿度与 5 分钟休息倒计时。
* **模式 D【免打扰休眠态 (Sleep)】**：
  * **进入条件**：语音指令“去睡觉”或长时间无交互超时。
  * **行为**：OLED 息屏（防烧屏降功耗），仅保留板载 PC13 灯低频呼吸，CPU 挂起非核心任务。
